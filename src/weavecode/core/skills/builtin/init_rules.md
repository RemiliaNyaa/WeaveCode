你要帮用户为当前项目（或全局）建立一份 `AGENTS.md` 规则文件。

**分两轮做。第一轮只分析和提问，绝对不要写文件；等用户回答后再写。**

## 第一轮：分析 + 提问

### 1. 先调查

优先读**信息密度最高**的来源：
- `README*`、根目录清单（`pyproject.toml` / `package.json` / `Cargo.toml`）、锁文件
- 构建 / 测试 / lint / 格式化 / 类型检查 / 代码生成的配置
- CI 工作流、pre-commit、任务运行器配置
- 已有的规则文件（`AGENTS.md` / `CLAUDE.md` / `.cursor/rules/` / `.github/copilot-instructions.md`）
- 项目本地配置（`.weave/config.json`）

读完配置和文档后如果架构还不清楚，再**有选择地**读少量有代表性的源码，找出真正的入口和模块边界。**不要随机翻叶子文件。**
**不要翻** `.git/`、`node_modules/`、虚拟环境、构建产物。

**优先信可执行的真源**：配置/脚本跟文档冲突时，以可执行的那份为准，只保留你**验证过**的内容。

### 2. 然后向用户提问

用一段话把下面的问题**一次列清**，让用户一次回答完：

1. **这份规则写到哪？**
   - **项目级** `.weave/AGENTS.md` —— 跟着这个项目走、可以提交到仓库
   - **全局** `~/.weave/AGENTS.md` —— 对这台机器上的所有项目生效
2. 你希望我**永远遵守**的偏好是什么？（用户选「全局」时才需要问）
3. 这个项目里有哪些**约定是代码里看不出来的**？例如：
   - 提交信息规范、分支 / PR 流程
   - 哪些目录不许动、哪些文件是生成的
   - 必须遵守的命令顺序（如 `lint → typecheck → test`）
   - 环境 / 凭据 / 服务的前置条件
4. 有没有**踩过的坑**，希望以后不要再踩？

### 3. 把已查到的事实一并给出

把你从代码里**已经确认**的事实整理成要点，连同上面的问题一起给用户。
然后**结束这一轮**，等用户回答。

**这一轮不要创建或修改任何文件。**

## 第二轮：写文件

用户回答之后：

1. 按用户选择的目标创建或改进文件：
   - 项目级：`.weave/AGENTS.md`（目录不存在就先创建）
   - 全局：`~/.weave/AGENTS.md`
2. **如果目标文件已存在：原地改进，不要整篇重写。** 保留已验证的有用内容，删掉废话和过时的说法，跟当前代码库对齐。
3. **只写这一个文件**，不要改动项目里的其他任何文件。
4. 全文控制在 **100 行以内** —— 它每轮对话都会被注入系统提示词，越短越好。
5. 写完向用户汇报：写到哪个文件、加了什么、改了什么。

## 写什么 / 不写什么

**要写**：
- 精确的命令和快捷方式（不写的话 Agent 一定会猜错）
- 怎么跑**单个**测试 / 单个包 / 一步聚焦的验证
- 命令的**顺序要求**
- 从文件名看不出、但很重要的架构说明
- 与语言/框架默认约定**不同**的约定
- 环境要求、配置怪癖、运维上的坑

**不要写**：
- 通用的软件建议
- 长篇教程，或**完整的目录树**
- 语言/框架显而易见的基本约定
- 没验证过的、推测性的说法

**判据**：每一行都要能回答 —— **「没有这条，Agent 是不是很可能会搞错？」** 答不上来就删掉。
